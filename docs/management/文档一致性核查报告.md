# 智能鱼缸 — 文档一致性核查报告

**核查日期**：2026-06-01  
**核查人**：项目经理 Agent  
**核查范围**：9 份项目文档的 GPIO 分配、成本预算、OLED 规格、零件尺寸、关键器件型号/单价等关键数据  
**核查方法**：逐字段交叉对比，按"文档 A 说 X / 文档 B 说 Y"格式列举差异

---

## 0. 摘要

| 类别 | 数量 | 严重等级 |
|------|------|----------|
| **致命不一致**（影响电路/编译/装配可行性） | 4 项 | 🔴 立即处理 |
| **严重不一致**（影响采购/成本/制造） | 7 项 | 🟠 需尽快处理 |
| **中度不一致**（影响技术参数/版本同步） | 8 项 | 🟡 计划整改 |
| **轻度不一致**（文档表述/格式） | 6 项 | 🟢 建议优化 |
| **合计** | **25 项** | — |

**最关键问题**：
1. **OLED SDA/SCL GPIO 在硬件/PCB 文档与 README/MEMORY 之间反向** → 固件按 MEMORY 写则电路不工作，按电路写则与 MEMORY 不一致
2. **固件设计说明书 仍写 DS18B20 用 GPIO2** → 编译会失败/读不到温度
3. **三套成本数字（60.5 / 91.75 / 92.2）口径不同但未注明** → 财务/采购/项目结项易混乱
4. **结构设计 v2.0 重组后，元器件采购清单未同步更新** → 接线端子、底座器件数量仍按 v1.0

## 1. 致命不一致（🔴 P0 — 影响功能）

### 1.1 【致命】OLED SDA/SCL GPIO 分配反向

| 文档 | 说法 | 位置 |
|------|------|------|
| README.md | GPIO0 = **SCL**，GPIO1 = **SDA** | L47-48 |
| MEMORY.md | GPIO0 = **SCL**，GPIO1 = **SDA** | L11-12 |
| 电路设计说明书.md | GPIO0 = **SDA**，GPIO1 = **SCL** | L32-33（架构图）、L131-132（电路连接） |
| PCB设计说明书.md | GPIO0 = **SDA**，GPIO1 = **SCL** | L39-40（引脚表） |
| 固件设计说明书.md | "GPIO0/1"（未区分 SDA/SCL） | L32, L403 |

**影响**：
- 硬件按电路/PCB 文档焊接：SDA→GPIO0、SCL→GPIO1
- 固件按 README/MEMORY 写：`Wire.begin(1, 0)` → SDA=GPIO1、SCL=GPIO0
- **结果：I2C 通信失败，OLED 不亮**

**判定**：硬件（电路+PCB）4 处写一致，软件（README+MEMORY）2 处写一致。需先确认**真值**（I2C 标准为 SDA/SCL，但 ESP32-C3 对 SDA/SCL 的引脚分配由硬件决定），再统一所有文档。

### 1.2 【致命】固件设计说明书 DS18B20 引脚仍写 GPIO2

| 文档 | 说法 | 位置 |
|------|------|------|
| README.md | DS18B20 = **GPIO7** | L52 |
| MEMORY.md | DS18B20 = **GPIO7**（强调避开 strapping 引脚） | L16, L21, L51, L56 |
| 电路设计说明书.md | DS18B20 = **GPIO7**（明确写"GPIO2 已用作DS18B20❌"） | L34, L155, L165, L375, L450 |
| PCB设计说明书.md | DS18B20 = **GPIO7** | L41 |
| 固件设计说明书.md | **DS18B20 = GPIO2** | L32（架构图） |

**影响**：
- 电路硬件走 GPIO7，固件代码按 GPIO2 初始化 OneWire → 读不到温度
- 电路设计说明书 L450 还专门标注"GPIO2 已用作 DS18B20 ❌"作为反面教材，**但固件文档恰恰落入此坑**
- MEMORY.md L57 记录"温度传感器改为 GPIO7（原计划 GPIO2）"，但固件文档未跟进

**判定**：固件设计说明书必须更新到 GPIO7。

## 2. 严重不一致（🟠 P1 — 影响采购/成本/制造）
